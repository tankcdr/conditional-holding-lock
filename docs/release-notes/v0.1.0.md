# conditional-holding-lock v0.1.0

Initial out-of-tree release of the Conditional Holding Lock reference code. The interface is a
strawman for the Conditional Holding Lock CIP and will change while the interface issues are open,
so expect to re-pin.

## What is attached

Three consumer DARs are attached to this release, plus the generated manifest
`conditional-lock-release.json` and `fixtures/hash-vectors.json`.

| Package | Package ID | Attached |
| --- | --- | --- |
| `splice-api-token-conditional-lock-v1` | `cc541d14181e265667ea06c6e738e2415881ec49f849474da63319fcfb10d5ac` | yes |
| `conditional-lock-utils` | `02e296d5a8317990106aebc51db5b20e0f1391646e03d0d23d18b25e5b10e5d3` | yes |
| `conditional-lock-test-token` | `245c8e38d10ca6e3c74cd9b3a3ef770cdecf616cee5d096b405fe4d712e6844f` | yes |
| `conditional-lock-test` | `7a9bb8ba33e2a01eb233e2eec929e406b39f557be491a2f8816f231798f1ce65` | no |

The per-DAR SHA-256 values are in `conditional-lock-release.json`, which is generated from the
built DARs by `scripts/make-release-manifest.py` — they are not transcribed by hand.

`conditional-lock-test` is not attached: it is the proof suite, it depends on `daml-script`, and no
consumer should put it in `data-dependencies`. It appears in the manifest with `"attached": false`.

**A DAR's SHA-256 is download integrity and the package ID is package identity; neither implies the
other.** The same compiled package can ship as two DAR files with different digests — zip entry
order, timestamps, and compiler interface files vary between builds — so rebuilding and getting a
different DAR digest is expected and is not a bug. Reproducibility here is a claim about package
IDs, checked by `scripts/verify-reproducible.sh`, which builds twice from clean `.daml/` trees and
compares `dpm inspect-dar` main package IDs for all four packages.

## Scope

**The three attached DARs are for non-Amulet registries.** **Canton Coin support follows Splice's
own track, because Amulet changes land through Splice and the CIP process on the maintainers'
schedule.** Nothing in this release targets Amulet.

## Build inputs

Daml SDK 3.5.2, Daml-LF 2.1, Splice release `0.8.1` (commit
`fb3c8c8a9259e98cdeb1cffc0cc77eaa7cc69e52`), built with `--explicit-serializable=yes --target=2.1`.

`SPLICE_PIN` was repinned from an untagged Splice `main` commit to the release tag `0.8.1`; all six
pinned DAR SHA-256 values were unchanged by that repin. Note that `canton-network/splice` tags are
unprefixed (`0.8.1`) while `digital-asset/decentralized-canton-sync` releases are spelled `v0.8.1`;
only the unprefixed form resolves on `raw.githubusercontent.com`.

This release is built and proven only at Splice `0.8.1`. Two of the six pinned DARs are not
available unchanged at earlier tags — `splice-test-token-v2-1.0.1.dar` does not exist at 0.7.4 or
0.7.5, and `splice-token-standard-utils-2.0.0.dar` has different bytes there — so no cross-tag
equivalence is claimed. The Daml proofs ran on local Canton 3.5.16 and 3.5.17 sandboxes through a
real Ledger API; this release has **not** been run against Mainnet.

## Versioning

The release version lives in the git tag, `CHANGELOG.md`, and the manifest. The four Daml packages
keep `version: 1.0.0` in `daml.yaml`, because a package ID is a content hash that includes the
package name and version, and the interface package ID is pinned upstream in Splice's
`daml/dars.lock` on the proposed branch of PR 7294; that pin is not yet on Splice `main`.

**Never re-tag.** A moved tag silently changes the bytes a consumer downloads while every recorded
SHA-256 stays the same, and nothing detects it. `scripts/check-pin.py` catches a moved *upstream*
tag by comparing the resolved commit against `splice_release_commit`.

## Network compatibility

Checked 2026-09-22: Mainnet Splice 0.8.0 / Canton 3.5.16, Testnet Splice 0.8.1 / Canton 3.5.17,
compiler 3.5.2 on both. This is a point-in-time claim and the networks drift faster than this file;
`just check-compatibility` is the live answer.

## Out of scope

`dpm publish` is out of scope for this release; GitHub Releases are the citable artifact channel.

DAR signing is out of scope for this release — the SHA-256 values in
`conditional-lock-release.json` are the only provenance.
