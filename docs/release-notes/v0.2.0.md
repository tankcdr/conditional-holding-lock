# conditional-holding-lock v0.2.0

Round three of the Conditional Holding Lock interface. The interface is still a strawman for a draft
CIP under review on [Splice PR 7294](https://github.com/canton-network/splice/pull/7294), so expect to
re-pin again.

## What changed

- **Recorded approvals.** `ConditionalLock_Approve` records an approval on the lock for an exact rule
  and list of legs, and `ConditionalLock_Enact` counts recorded approvals toward `Guard_Parties` and the
  enactor requirement. The parties of a threshold approve one at a time from their own wallets, with no
  registry delegation contract. The off-ledger API gains the `approve` choice-context route.
- **Ledger-time bounds.** Every time check in `conditional-lock-utils` and the TestTokenV2 adapter is a
  bound on ledger time (`isLedgerTimeGE`, `isLedgerTimeLT`) instead of a `getTime` read, which limited
  the delay between preparing and submitting a transaction to one minute (CIP-0062). Accept and reject
  boundaries and error messages are unchanged.
- **Package versions follow the release.** Every first-party Daml package is `0.2.0`, and the DAR
  filenames say so (`*-0.2.0.dar`). Canton will not vet two packages with the same name and version,
  so v0.1.0's `*-1.0.0.dar` could not have been upgraded in place.

## Breaking changes

- The interface package ID changes, from `cc541d14...` to `ff9cd018...`, because the interface gained
  a choice, a view field and an action. Splice PR 7294's `daml/dars.lock` carries the new ID.
- `ConditionalLockView` has a new `approvals` field and `ConditionalLockAction` a new `CLA_Approve`
  constructor; registries implement `conditionalLock_approveImpl` and
  `conditionalLock_approveExtraObservers`.
- In `conditional-lock-utils`, `satisfied` returns `Update Bool` and `validateTerms` no longer takes a
  `Time`. [docs/adoption.md](../adoption.md) lists both signatures.

The per-DAR SHA-256 values are in `conditional-lock-release.json`, generated from the built DARs. A
DAR's SHA-256 is download integrity and the package ID is package identity; neither implies the other.
`conditional-lock-test` is the proof suite and is not attached.

## Proven

94 Daml Scripts pass on the IDE ledger and on local Canton 3.5.16 (Mainnet) and 3.5.17 (Testnet)
ledgers through a real Ledger API. On the repository's localnet at the Mainnet release (Splice 0.8.0),
`pnpm test:integration` settles the CIP-0112 DvP example with real Canton Coin as the payment leg
against TestTokenV2 locked under this interface, and 77 of the 94 scripts run there (the other 17 need a
controllable clock). The evidence files under `docs/runbook/` were recorded before this release and are
regenerated at this tag separately.

## Scope

The attached DARs are for non-Amulet registries. Canton Coin support follows Splice's own track. This
release has not been run against a public network.

## Build inputs

Daml SDK 3.5.2, Daml-LF 2.1, Splice release `0.8.1` (commit `fb3c8c8a9259e98cdeb1cffc0cc77eaa7cc69e52`),
built with `--explicit-serializable=yes --target=2.1`. Network reference checked 2026-09-24: Mainnet
Splice 0.8.0 / Canton 3.5.16, Testnet Splice 0.8.1 / Canton 3.5.17; `just check-compatibility` is the
live answer.

**Never re-tag.** A moved tag silently changes the bytes a consumer downloads while every recorded
SHA-256 stays the same.
